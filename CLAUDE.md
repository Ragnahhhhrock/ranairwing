# RAN Air Wing: instructions for Claude sessions

Project: browser flight sim of HMAS Melbourne (R21) and her air wing, set 1977-1982. Live at https://ranairwing.com (GitHub Pages from `main`). The sim is one file, `index.html`.

## Always
- **Other sessions edit this repo too (sim features, About page).** `git pull --rebase origin main` before you push, and re-read `index.html` before you write about it: posts must match the current sim. The owner's contact address is contact@ranairwing.com.
- **Commit every update and push to `main`.** The owner wants every change committed to this repo automatically.
- **Every new sim feature gets a blog post in the same commit.** See "Feature posts" below.
- Follow `docs/style-guide.md` for anything visual or written.
- Do not state history as fact without a source. History posts need a `sources:` list in the front matter. If you cannot verify something, leave it out and say so.
- Only publish screenshots from the sim. Do not publish the reference photographs (they belong to others).

## Feature posts
When you add or change a player-visible feature:
1. Write `content/posts/<slug>.md` (front matter: `title`, `date` as `YYYY-MM-DDTHH:MM+08:00`, `categories`, `summary`, `shot`, `hero_alt`; quote any value containing a colon). Use category `dev-diary` plus any others that fit. Date it now so it publishes at once; do not take a scheduled slot.
2. Add a screenshot recipe to `content/shots.json` and capture it: `python3 tools/blog/shoot.py <shot-id>` (recipe fields: `cam`, `hour`, `sea`, `speed`, `start` of cat/approach/tutapp, `view`, `ac`, `keys`, `advance`, `lesson`). Look at the image before committing.
3. Describe what it does, how to try it (keys), and what is still approximate. Check every claim against the code in `index.html`.
4. `python3 tools/blog/build.py`, then commit `content/`, `blog/`, `sitemap.xml` together with the feature.

If you commit a `feat:` change without a post, the GitHub Action drafts one from the commit message (trailers `Blog-Summary:`, `Blog-Categories:`, `Blog-Shot:`, `Blog-Try:`, `Blog-Skip: true`). Prefer writing the post yourself.

## Blog
- Source: `content/posts/*.md`. Output: `blog/` and `/sitemap.xml`, generated by `tools/blog/build.py` (10 posts per page, category pages, share buttons, RSS).
- The 90-day plan is `content/schedule.json` (generated by `tools/blog/make_schedule.py`; see `docs/content-schedule.md`). A post with no `date:` takes its slot's date. Times are randomised on purpose; do not round them or move them to the same time of day.
- Posts whose time has not arrived are not published. `.github/workflows/blog.yml` rebuilds every 30 minutes, so a post goes live within about 30-60 minutes of its slot. `python3 tools/blog/build.py --all` previews everything locally.
- Slots marked `brief` in `docs/content-schedule.md` need sourced research before writing. Move a post from brief to written by adding its Markdown file with the slot's slug, then rerun `make_schedule.py`.
- `.nojekyll` must stay: without it GitHub Pages would publish the unreleased Markdown files.

## Sim facts to keep consistent
Ship heading is fixed at 250 degrees into a 250-degree wind; sea states 0-6 give 2, 5, 9, 14, 19, 25, 32 kn of wind; five wires; angled deck 5.5 degrees; glidepath 3.5 degrees. If you change any of these, update the posts that quote them (`grep -r` the blog source).
